## Objetivo

Esta seção documenta os métodos de integração entre o seu ERP e a plataforma Nexfar. A integração acontece em dois sentidos:

- **Entrada de dados** — a Nexfar precisa acessar informações do seu sistema (clientes, produtos, condições comerciais, estoque).
- **Saída de pedidos** — a Nexfar envia para o seu sistema os pedidos aprovados na plataforma.

---

## Saída de Pedidos

<CardGroup cols={2}>
  <Card title="Webhook de Pedidos" icon="webhook" href="/integration/webhook-pedidos/overview">
    A Nexfar envia cada pedido aprovado para o seu endpoint via HTTP POST

    - Modelo push, em tempo real
    - Sem necessidade de polling
    - Requer endpoint HTTPS exposto pelo distribuidor
  </Card>
</CardGroup>

<Note>
  O Webhook de Pedidos é independente do método escolhido para entrada de dados — você pode, por exemplo, enviar cadastros via Banco de Dados e receber pedidos via Webhook.
</Note>

## Escolhendo o Método Ideal

Cada método de integração possui características específicas:

### Banco de Dados
- **Melhor para**: acesso direto e em tempo real aos dados
- **Requisitos**: liberação de IPs (whitelist) via NAT ou VPN site-to-site
- **Vantagens**: performance, dados atualizados, queries customizadas

### API Nexfar
- **Melhor para**: integrações modernas em que o distribuidor ou indústria nos envia os dados
- **Requisitos**: desenvolvimento de integração com a [API de Ingestão](/integration/api-ingestion/overview)
- **Vantagens**: flexibilidade, facilidade de manutenção e atualização

### REST API do ERP
- **Melhor para**: ERPs que já expõem uma API própria e preferem ser consultados
- **Requisitos**: endpoints REST com paginação e filtros conforme o contrato Nexfar
- **Vantagens**: reaproveita API existente, sem desenvolvimento de envio

### ERPs Homologados
- **Melhor para**: distribuidores que usam um ERP já integrado pela Nexfar
- **Requisitos**: cada ERP tem requisitos individuais que devem ser observados
- **Vantagens**: regras já mapeadas, integração testada em múltiplos clientes

### FTP/SFTP e EDI
- **Melhor para**: transferência de arquivos EDI e/ou processamento em lote
- **Requisitos**: servidor FTP/SFTP configurado
- **Vantagens**: simplicidade, processamento batch, baixo acoplamento
